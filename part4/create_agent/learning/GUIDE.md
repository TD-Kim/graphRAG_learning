# create_agent 읽기 가이드

강의: Part 4 / CH01-01 AI Agent 이해하기, CH01-02 도구 기반 Agent 구현하기

| 파일 | 역할 |
|---|---|
| [`langchain_create_agent.ipynb`](../langchain_create_agent.ipynb) | LangChain `create_agent` 로 도구를 쓰는 에이전트 만들기 (DB 없음) |

## 한눈에 보기

```
사용자 메시지 ─▶ [model] LLM: "도구가 필요한가?" ──아니오──▶ 최종 답변
                      │ 예 (tool_call: 이름 + 인자)
                      ▼
                 [tools] 함수 실행 ─▶ 결과(ToolMessage) ─▶ 다시 [model] 로 (반복)
```

Part 3 의 ToolsRetriever 는 "도구를 한 번 골라 검색"했다. 에이전트는 **결과를 보고 다시 생각해서 또 도구를 부르는 반복(루프)** 이 있다.
`agent.get_graph()` 로 그려 보면 model ↔ tools 사이의 순환이 보인다(셀 5).

## 읽는 순서

| 셀 | 핵심 |
|---|---|
| 4 | 가장 작은 에이전트: 모델 이름, 도구 목록, 시스템 프롬프트 |
| 5 | 에이전트 구조를 그림으로 (`draw_mermaid_png`) |
| 6~7 | 응답의 `messages` 를 하나씩 출력: Human → AI(tool_call) → Tool → AI(답변) |
| 9 | `@tool(parse_docstring=True)`: **docstring 이 도구 설명, Args 가 인자 설명** |
| 12~13 | 도구 3개 중 알맞은 것을 고르기 |
| 14 | `stream(stream_mode="updates")`: 노드가 끝날 때마다 무엇이 일어났는지 |

## "왜"

- **도구 = 이름 + 설명 + 입력 스키마 + 함수**: LLM 은 함수 코드를 보지 못한다. 이름, docstring, 타입 힌트만 보고 언제 어떻게 부를지 정한다. 그래서 docstring 이 곧 사용 설명서다.
- **타입 힌트**: `birth_year: int` 이면 LLM 이 `"1990년"` 이 아니라 `1990` 을 넣게 된다(입력 스키마로 변환됨).
- **도구는 문자열을 돌려준다**: 결과가 다시 LLM 에게 메시지로 들어가므로, 사람이 읽기 좋은 문장이 LLM 에게도 좋다.
- **messages 를 직접 찍어 보는 이유**: 에이전트가 틀렸을 때 "도구를 안 불렀는지, 잘못된 인자로 불렀는지, 결과를 잘못 읽었는지"를 구분할 수 있는 유일한 방법이다.
- **stream**: 에이전트는 여러 단계를 거치므로 오래 걸린다. 중간 과정을 보여 주는 UI(Part 4 챗봇)의 기초.

## 생각해 볼 점

1. 질문 하나에 도구 두 개가 필요할 때(셀 14) 에이전트는 두 도구를 **동시에** 부를까, **차례로** 부를까? 출력에서 확인해 보자.
2. `calculate_age` 는 `현재 연도 - 출생 연도 + 1` 이다. 한국식 나이와 만 나이 중 무엇인가? 도구 설명에 그 사실이 있나? (도구 설명이 모호하면 답변도 모호해진다)
3. `get_weather` 는 항상 "맑음"을 돌려주는 가짜 도구다. 에이전트는 그 결과를 의심할까? 도구 결과를 그대로 믿는 것이 왜 위험할 수 있나?
4. 도구가 예외를 던지면 에이전트는 어떻게 될까? 일부러 0 으로 나누는 도구를 만들어 보자.
